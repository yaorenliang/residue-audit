# residue-audit

**用第三方的眼光，测量一个隐藏的植入物到底留下了什么。**

多数安全工具回答的是「我们检测到了吗」。这个项目问的是更难伪造的那个问题：
**「它试图藏起来之后，主机上还剩什么能看见？」**

三项检查，一个立场：**复算，而不是自证。**

| 检查 | 它回答什么 |
|---|---|
| `residue trace` | 植入物落下的产物，真的融进邻居了吗——文件 mtime、目录顺序、旁证条目 |
| `residue dwell` | 给定台账与检测命中，它活了多久，其中多少是真被规则覆盖的 |
| `residue batch` | 同族两次构建是否互相可区分，还是一条特征就能把它们聚成一类 |

## 状态

`v0.0.0` —— 仓库骨架。三项检查在 `v0.1.0` 落地。
这里的任何子命令都不会对主机执行动作：它只读路径和 JSON，返回判定。

## 设计立场

1. **复算，不自证。** 「时间戳已对齐」这句话，如果由做对齐的那个程序自己打印，价值为零。
   每项检查都设计成可以被第二个独立实现复现出同一个数字。
2. **每项检查都有负控。** 如果找不到能让它失败的输入，它就不是检查。
3. **局限是输出的一部分。** 每条判定都带 `why` 与 `evidence`；每项检查都写明它**判不了**的情况。

## 边界

做：文件系统元数据一致性、驻留时间与检测覆盖度量、跨批相似度评分。

永远不做：载荷投递、横向移动、持久化安装、凭据获取，以及任何作用于「它没被指向的主机」的行为。

## 复现

```bash
git clone https://github.com/yaorenliang/residue-audit
cd residue-audit
make demo        # 仅夹具，不起 VM，不联网
```

`make lab` 会在无外网的 QEMU guest（真 ext4）上跑同一套夹具——因为 macOS 和 ext4
对目录 mtime 的语义并不一致，而这恰恰是复算的关键。
