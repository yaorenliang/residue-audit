# 残迹审计：我怎么验证一个木马到底藏得多深

凌晨三点，你手里有一台主机、一份内存镜像、一个从别处抄来的 IoC 列表。

你要回答的问题不是「它是什么」——样本总会有人分析。你要回答的是：
**它在这儿待了多久，藏到了哪一层，以及我这套看法有没有可能只是自我安慰。**

事故报告的最后一段通常这么写：*未发现持久化痕迹。* 这句话有两个截然不同的意思。
一个是「它不在这儿」。另一个是「它在这儿，而我们看的方式看不见它」。
这两句话在纸面上长得一模一样，在事后复盘里代价差得很远。

这个项目只做一件事：把这两句话分开。

## 一、我先被自己的工具骗了一次

在把它做成工具之前，它是我自己的一次翻车。

那套植入物会把持久化单元写进 `/etc/systemd/system`，然后把每个文件的 mtime
改到与同目录里最新的邻居一致——这样任何人敲下 `ls -lt`，看到的就是一排整齐的老文件。
我写了检查器去验证这件事，跑出来是 aligned：全部对齐。

它是错的。

漏掉的是客户端二进制。那个二进制被写进 `/usr/local/bin`，目录里预先没有任何东西，
对齐代码找不到可借的时间戳，于是跳过；而检查器在同一个目录里也找不到「非自家」的邻居，
于是拿产物自己当邻居，比完得出「不比邻居新」。

**同一次判断，既是识别，又是测量，还是结论。** 产物给自己做了旁证。

这不是一个实现 bug，这是一个结构性的失败模式：**自证**。
程序说「我把它藏好了」，程序再检查「它藏好了吗」，程序打印「藏好了」。
三段话出自同一套假设，中间没有任何一个环节允许别人插嘴。

修法也不是补一个 if。是把这三件事拆开：

* **识别**（哪些文件算「自家的」）——启发式，必须被明确标注为启发式；
* **测量**（mtime、inode、邻居上限）——纯元数据，任何有 `stat(1)` 的人都能重做；
* **判定**（对齐/不对齐）——一条可以被别人推翻的判据。

拆开之后，第一个立刻冒出来的东西，是我原本不想看的：**这个目录里根本没有旁证**。
没有旁证的时候，「对齐」不是一个结论，是一个假设穿着结论的衣服。
工具从那以后在这种目录里返回 `partial`，理由写得很直白：*对齐无法被证明，只能被假设。*

## 二、第二次翻车发生在真机上

修完旁证那条，我以为识别这件事已经干净了。然后在真的 Ubuntu 上跑了一遍。

结果是这样的：认领 13 个文件，其中 5 个是我的，8 个不是。**精度 38%。**

那 8 个是 `/usr/libexec/packagekitd`、`/usr/libexec/boltd`、`/usr/libexec/qmi-proxy`、
`packagekit-direct`、`pk-debconf-helper`、`pk-offline-update`、`mbim-proxy`，
还有 `/etc/cron.d/e2scrub_all`。它们每一个都由一个正常安装的 systemd 单元正常启动。

原因很简单，也很丢人：当时的规则是「任何单元的 `ExecStart=` 提到的任何文件都算自家的」。
在一台只有五个文件的夹具树上，这条规则完美；在一台装了包管理、蓝牙、蜂窝模块的机器上，
它把系统自带二进制一网打尽。**我的夹具太干净，所以我的规则看起来是对的。**

这件事改掉了识别层的设计。新规则锚在**模式的证据**上，而不是锚在「谁提到谁」上：

1. 正文带产物标记（`KillSignal=SIGCONT`、`SendSIGKILL=no`）的单元，算自家的；
2. 这种单元启动的文件，算自家的；
3. 正文提到上述路径的文件，算自家的——这一条抓 cron：它自己没有标记，但一定会写它要跑的程序。

同一个 root，认领 5 个、误报 0 个。代价是那 8 个文件现在变成「弱认领」，完全不参与审计。
我没有把这个代价藏起来，它出现在输出里：`(+8 weak claim(s) not audited)`。
想要旧行为的人可以加 `--broad`，然后自己承担 38%。

这两次翻车的形状是一样的：**判断被当成了测量。**
第一次是「我认领的文件」被拿去给我的结论作证；第二次是「我认领得对不对」这件事本身
没有被度量过。两次的修法也一样：把判断从测量里拆出来，给它单独的位置、单独的数字、
单独的一句「我可能会错」。

## 三、三个问题，三种残迹

一个想藏起来的植入物，能动的只有三样东西：**时间**、**顺序**、**注意力**。
三样东西的地板都不一样高。

### 时间：mtime 可以借，ctime 不可以

改 mtime 是一个正常的系统调用，`utimensat(2)`，任何用户态程序都能调。
所以「时间戳对齐」这件事，做起来一点都不难：读一下邻居的最新 mtime，把自己改成一样。

但改 mtime 这个动作本身，会把文件的 **ctime**（状态变更时间）推到当下。
而 ctime 没有对应的系统调用可以写——它不是「文件的属性」，它是「内核记账的结果」。
你可以让一个文件声称自己来自 2019 年，同时无法阻止内核在旁边写下：*这个声称发生在今天。*

于是 `residue trace` 的第 4 条检查长这样：

```
trace.ctime   fail   5 artifact(s) have a ctime newer than every sibling:
                     mtime can be borrowed, ctime cannot
```

这是「深藏」的第一块地板，而且它比大多数人以为的低。
一次真正干净的投递，需要整个文件系统在同一时刻被构建——也就是做镜像，而不是做投放。

### 顺序：inode 没有 syscall

第二块地板更低。

多数 Linux 文件系统单调分配 inode 号。你先写的文件号小，后写的大。
没有任何用户态调用能重编一个 inode 号：你不能「把 4021 改成 1180」。
你能做的只有改时间戳、改权限、改扩展属性——都是 inode 之外的字段。

所以把目录里所有文件的 inode 排一下序，创建顺序就回来了：

```
trace.order   fail   5 artifact(s) have a higher inode than every sibling,
                     so creation order is recoverable
```

这一条几乎不可能通过。它不是「检测能力强」，它是「这一层根本没有藏的空间」。
把它打印出来，比假装它不存在有用：**深度是有地板的，工具的责任是把地板画出来。**

### 注意力：分母是被做手脚的地方

前两个问题是「藏不藏得住」，第三个问题是另一回事：**看见了多久。**

现实里的报告长这样：*该主机自 3 月 12 日起被控，持续 41 天，期间共触发 3 条告警。*
这句话里藏着三个可以随意揉捏的决定：

**分母是什么。** 如果分母是「所有被观察过的主机」，那操作者只要多扫、少投，
覆盖率就会自己变好看——扫一百台、投十台，命中两台，覆盖率 2% 看起来像「检测很弱」，
其实是「分母被灌了水」。所以分母只能是**走到投放这一步的主机**。只被扫过的主机没有东西可检测。

**前置和后置要不要分开。** 植入物还不存在的时候规则就响了，那是误报，不是覆盖。
把两者折进同一个比例，检测栈会显得比真实更好——而报告读者没有办法从那个百分比里看出来。

**恰好的 50% 算不算多数。** 不算。`> 50.0` 才通过，`50.0` 是
`partial-coverage`，理由就一句话：*exactly half or less is not coverage*。
没有任何命中的数据，覆盖率是 `unknown, not zero`——零是一个测量结果，「我们没看」不是。

这些都不是技术难点，是措辞纪律。而措辞纪律恰恰是这类报告最容易失守的地方。

## 四、为什么要第二个实现

拆开识别与测量之后，还剩最后一个自证的口子：**测量本身**。

于是有了 L3：`tests/cross_check.sh`。

做法很土。`residue` 只负责**认出**哪些文件是产物（从它自己的 JSON 输出里抠路径），
**测**这一步全部交给 shell 与 `stat(1)`：拿每个文件的 mtime，和同目录里所有非产物的
mtime 取最大值，比一遍，数出「几个超了」。

```
CROSS_ALIGNED=5   RESIDUE_ALIGNED=5
CROSS_LEAKS=0     RESIDUE_LEAKS=0
CROSS_MATCH=1
```

两个数一致，才算这个测量成立。不一致的时候，错的一定有一方，而且**不一定是 shell 那一方**。

这套东西真正起作用，是在它开始推翻我自己的时候。
第一版 trace 说「全部对齐」，L3 说「六个产物里有一个超了」——超的就是那个客户端二进制。
后来发现是桥接侧的对齐代码只在成功时改时间，失败时静默跳过；
再后来发现连「成功」的判断本身都是错的：目录上限里把产物自己算进了邻居。

修完之后，我把这件事写进了文档里的一句话：**没有 L3，「复算过」等于「同一个程序说了两遍同样的话」。**

## 五、地板在哪，以及为什么不假装它不在

一个诚实的测量工具，价值一半在它查得出什么，另一半在它**写明查不出什么**。
`docs/limits.md` 里每一条都是真的会咬人的：

**目录。** 创建文件会更新父目录的 mtime，也会更新父目录的 ctime，而 ctime 设不了。
所以老练的响应者一条 `stat /etc/systemd/system` 就看见：目录在 03:14 变过，
而里面每个文件都声称来自 2019 年。**这个工具目前还没有对目录 ctime 单独开一条检查。**
这是它最可能在一台人眼一看就脏的主机上给出 `pass` 的地方，我把它写在了 README 的
Limits 第一段里——不是等别人发现。

**进程。** 运行中植入物的字符串在内存里，映射发生在你挂载之前。
`/proc/<pid>/exe` 背后的二进制即使文件被删掉也仍然可读。
这个工具不读 `/proc` 下任何东西，所以它可以在一台仍然被控的主机上报告一个干净的文件系统。

**删除。** 未链接的 inode 还活在页缓存和日志里。产物在你挂载前被删掉，它就从视野里消失了。

**启发式识别。** 持久化机制不像 systemd 的植入物——shell profile 里的一行、
一个 `LD_PRELOAD` 条目、一行用 `/bin/sh -c` 内联载荷的 cron——不会被认领，
而未被认领的产物根本不会被测量。**工具对这类文件的沉默，不是一个发现。**

**跨构建相似度。** 对字符串算 Jaccard 只回答一个问题：两次构建的字符串集合重合度是否超过阈值。
两次构建可以坐在 0.90，却依然被控制流形状、函数次序、常量表一眼聚成一类。
低分不是「不可关联」的证据，它只是「这个投影没能把它们分开」。

把这些写清楚，会让人不舒服：它削弱了工具的说服力。
但也正是这一点让它有说服力——**一个测量工具的价值，在于它能被反对。**

## 六、所以它只发「怎么测」

这个项目是从一套完整的攻击链里长出来的：投放、横向、持久化、反取证、命令通道。
那些部分我一行都没有放进来，也不会放。

理由不是姿态，是方法：如果仓库里有一套能直接跑起来的投放链，那么所有关于「测量」的讨论
都会失去意义——读者无法区分「这个工具测出来了」和「这个工具的作者知道怎么打」。
一个审计工具必须站在审计方的位置上，它的每一行代码都必须能被受害者用来反对作者。

所以这里只有：

* 一棵能重建的夹具树（五件合成产物，写文本文件，然后退出）；
* 三个只读的判据；
* 一台没有外网、仓库只读挂载的 QEMU 客机；
* 一个把同一批数字用 `stat(1)` 再算一遍的 shell 脚本；
* 以及一份写明「我查不出什么」的文档。

植入物是合成的。这不是妥协，这是必要条件：**只有合成的植入物，才能让「它藏得怎么样」
变成一个可以被别人重复的问题。**

## 七、三分钟，自己跑一遍

```bash
git clone https://github.com/yaorenliang/residue-audit
cd residue-audit
make demo     # 零依赖，不联网，不需要 root
make verify   # 15 条单测 + L3 交叉复算
make lab      # 真实 ext4 客机，无外网；同架构约 90 秒，跨架构模拟几分钟
```

`make demo` 打印三段结论，中间那段是负控——把同一棵树改成「刚刚写入」，
对齐判据必须失败。没有负控的通过，只是没测。

第四段是覆盖率：五台主机，四台走到投放，命中两台，正好 50%。工具给
`partial-coverage`，不给 `covered`。这一行是整个仓库里我最在意的输出：
它拦下的不是攻击者，是写报告的人。

## 八、结语：把「我们什么都没发现」换成一句更长的话

安全报告里最贵的一句话是「未发现」。它听起来像结论，其实是关于观察方法的一句话，
只是没人把它写全。

我想让它变成两句：

> 我们本可以在**这一层**发现它——文件元数据、创建顺序、目录时间、驻留曲线；
> 我们不可能在**那一层**发现它——内存、已删除的 inode、以及所有我们没有被交到手里的规则。

第一句需要工具。第二句需要诚实。两句话一起，才叫一次审计。

深度是有边界的。把边界画出来，比声称没有边界，更有用。
