# 方法

三项检查，一个立场：**复算，而不是自证。**

一个测量只有做到「别人不信产出它的那个程序，也能得到同一个数」，才算数。
下面每一节都按这个标准写：换一门语言、换一把 `stat(1)`、换一个人，都能重做一遍，
并且有权不同意。

## trace —— 产物真的融进邻居了吗

植入物落地会留下两类残迹：文件本身，以及这些文件的元数据相对于周围一切所呈现的形状。
`trace` 读一棵根目录（挂载的镜像、活着的主机、夹具树），回答三个可以分开的问题。

**一、对齐。** 把每个产物的 mtime 和同目录里**不属于自己的最新邻居**比。产物比所有邻居都新，
它就跳出来了——任何人拿到可疑主机，第一条命令都是 `ls -lt`。对齐是从邻居那里借时间戳，
所以邻居必须存在。

**二、旁证。** 这正是「对齐」和「旁证」必须是两条检查的原因。目录里没有非自家条目时，
没有东西可借，「已对齐」就是一句披着判定外衣的假设。工具给 `partial`，不给 `pass`。
这不是假想情形：最小镜像上空的 `/etc/cron.d` 就是。

**三、新鲜度。** 对齐可以是对的，同时又是假的：如果整棵树是九十秒前写的，
「不比邻居新」的产物依然一眼就是同一批货。新鲜度比的是墙上的钟，不是目录。

第四个问题——创建**顺序**——会被报告，但很少通过。多数文件系统单调分配 inode，
最后写的文件 inode 最大，用户态没有任何调用能改变它。这是「一次投递最多能藏多深」的
地板，工具把地板指出来，而不是假装没有。

### 识别与测量要分开

哪些文件算「自家的」是一次判断，也是工具唯一依赖启发式的地方。规则刻意做窄，
而且锚在**模式的证据**上，而不是锚在「谁提到谁」上：

1. 正文带产物标记（`KillSignal=SIGCONT`、`SendSIGKILL=no`）的单元，算自家的；
2. 这种单元的 `ExecStart=` 所启动的文件，算自家的；
3. 正文提到上述路径的文件，算自家的——这条专门抓 cron 条目：
   它自己不携带标记，却一定会写它要执行的程序。

窄是有实测依据的，不是凭感觉。第一版规则宽得多：**任何**单元的 `ExecStart=`
提到的**任何**文件都算自家的。在标准 Ubuntu 24.04 root 上，那条规则认领了 13 个文件，
其中只有 5 个是我们的——**精度 38%**。原因是 `packagekitd`、`boltd`、`qmi-proxy`、
`packagekit-direct`、`pk-debconf-helper`、`pk-offline-update`、`mbim-proxy` 和
`/etc/cron.d/e2scrub_all`，全都合法地由合法安装的单元启动。
在活主机上这不是小误差：它把系统自带二进制变成发现。

改成锚在标记上之后，同一个 root 上是 5 个认领、0 个误报，代价是：
宽规则本来会认领的 8 个文件现在被记为**弱认领**，完全不参与审计。
这个交换写在输出里（`(+8 weak claim(s) not audited)`），不是藏起来。
`--broad` 可以恢复旧规则，用于「宁可多认也不愿漏」的场合。

识别之后**被测量**的一切——mtime、inode 次序、邻居上限、ctime——都是元数据，
任何人都能用 `stat` 重算。那部分必须经得起不信任；识别那部分必须被标注。

## dwell —— 活了多久，其中多少被真正看见

事件报告里有两个数经常被混为一谈：植入物存在了多久，以及检测栈实际看到了其中多少。

台账是 ndjson：`{"ts": 1180, "host": "h1", "event": "mine"}`。
`dwell` 从中算出每台主机的驻留跨度、总体分布和覆盖率。

覆盖率有两条规则，因为朴素版本是错的：

* 分母是走到 `deploy` 的主机，不是观察到的全部主机。只被扫过的主机没有东西可检测；
  把它算进分母，等于允许操作者靠「多扫少投」美化自己的覆盖率。
* 投放前的命中与投放后的命中分开计数。植入物还不存在时规则就响了，那是误报；
  把它折进同一个比例，会让检测栈显得比真实更好。

还有一条关于措辞的规则：**恰好一半不算多数**。`rate > 50.0` 才通过；50.0 是
`partial-coverage`。没有提供任何命中时，覆盖率是 `skip`，理由写 `unknown, not zero`——
零是一个测量结果，「我们没看」不是。

## batch —— 一条特征能不能把两次构建聚成一类

同族的两次构建，不该互相认得出。`batch` 拿特征集（字符串、符号表，谁来提取都行），
两两算 Jaccard 相似度，与阈值比较。

有意思的不是「不同」，是「几乎一样」：0.99 的一对，人看两张文件清单觉得是两样东西，
聚类器看是同一件。`threshold - 0.02` 到 `threshold` 之间的窄带故意报 `partial`——
那条线附近，再多一次构建就会翻盘，此时的「通过」是把掷硬币说成事实。

## 四层验证

```
L0  契约      夹具 -> golden JSON，逐字段比对
L1  负控      每条检查都配一个它必须不通过的输入
L2  真 ext4   同一套夹具放进无外网的 QEMU guest（手动）
L3  交叉复算  第二个实现用 stat(1) 把数字重算一遍
```

L0 与 L1 在 CI 上跑 Linux 与 macOS。L2 需要 qemu，手动跑。L3 是
`tests/cross_check.sh`：residue 负责识别，shell 负责测量，两个计数必须一致。

没有 L1，「通过了」等于「没测」；没有 L3，「复算过」等于「同一个程序说了两遍同样的话」。
